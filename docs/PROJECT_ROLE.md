# Language Teacher — Project Role

## 1. Роль проекта

**Language Teacher** — персональный преподаватель иностранных языков и языковой тренер в формате PWA-приложения.

Главная задача приложения — помогать человеку практически изучать разные языки для реального общения, а не проходить абстрактные уровни, набирать очки или поддерживать игровые серии.

Приложение не привязано к одному языку. Пользователь может добавлять и изучать разные языки, а Language Teacher должен адаптировать обучение под каждый язык отдельно.

Основная цель:

> превратить изучаемый язык из учебного предмета в инструмент реального общения.

---

## 2. Основные принципы

Language Teacher должен одновременно развивать:

- разговорную речь;
- понимание речи на слух;
- произношение и интонацию;
- словарный запас;
- практическую грамматику;
- построение естественных фраз;
- чтение;
- быструю реакцию в реальном разговоре.

Эти навыки не должны преподаваться как полностью отдельные предметы. Одно занятие может одновременно включать слушание, речь, лексику, произношение и грамматику.

Главный принцип:

> **меньше пассивного чтения о языке — больше активного использования языка.**

---

## 3. Multi-language first

Language Teacher изначально проектируется для нескольких языков.

Пользователь может:

- добавить новый язык;
- переключаться между изучаемыми языками;
- иметь отдельный прогресс для каждого языка;
- иметь отдельную историю ошибок;
- отдельный словарь;
- отдельную очередь интервального повторения;
- отдельные жизненные ситуации;
- отдельный профиль произношения;
- отдельные настройки сложности.

Язык не должен быть жёстко зашит в интерфейс или код приложения.

---

## 4. Single-user first

Базовая модель приложения:

**одна установленная копия Language Teacher = один основной пользователь.**

Полноценная multi-user система не нужна для MVP.

При этом внутри архитектуры данные должны быть связаны с внутренним `userId`, например:

```json
{
  "userId": "local-user"
}
```

Это позволит в будущем без серьёзной переделки добавить:

- семейные профили;
- несколько пользователей на одном устройстве;
- аккаунты;
- синхронизацию между устройствами;
- облачное хранение.

Но в первой версии пользователь не должен видеть экран выбора профиля.

---

## 5. Первый запуск и настройка языка

При добавлении языка приложение должно быстро определить:

1. какой язык пользователь хочет изучать;
2. зачем он ему нужен;
3. насколько уверенно пользователь уже понимает и использует язык;
4. какие жизненные ситуации для него особенно важны.

Не следует начинать с формального CEFR-теста.

Можно спросить:

- Я почти ничего не знаю.
- Я понимаю отдельные слова.
- Я могу строить простые предложения.
- Я разговариваю, но часто ошибаюсь.
- Я уже довольно свободно говорю.

CEFR A1–C2 может использоваться внутри системы как дополнительная техническая метрика, но не должен быть главным способом описания навыков пользователя.

---

## 6. Language Intelligence

При добавлении нового языка Language Teacher должен сформировать профиль языка.

Он может включать:

- особенности произношения;
- ударение;
- чтение;
- наиболее важные грамматические конструкции;
- частотные современные слова;
- устойчивые выражения;
- разговорные chunks;
- формальную и неформальную речь;
- типичные ошибки;
- ложных друзей;
- особенности живой речи;
- важные бытовые ситуации;
- различия относительно языков, которые уже знает пользователь.

Для нового языка приложение может использовать разрешённые внешние источники и web research для формирования Language Knowledge Base.

Результат должен сохраняться и переиспользоваться, а не исследоваться заново при каждом запуске.

---

## 7. Разговорная практика

Особый акцент делается на языке, который реально используется в повседневной жизни.

Приложение должно создавать короткие реалистичные ситуации:

- знакомство;
- магазин;
- ресторан;
- кафе;
- транспорт;
- банк;
- врач;
- аптека;
- соседи;
- работа;
- телефонный разговор;
- путешествие;
- просьба о помощи;
- small talk;
- аренда жилья;
- общение с администрацией;
- объяснение проблемы.

В Conversation Mode приложение играет роль собеседника.

Правило:

1. сначала дать пользователю возможность ответить самостоятельно;
2. не подсказывать готовый ответ сразу;
3. понять намерение пользователя;
4. исправить только существенные ошибки;
5. предложить более естественный вариант;
6. продолжить разговор.

---

## 8. Исправление ошибок

Language Teacher не должен исправлять каждую мелочь.

В первую очередь исправляются ошибки, которые:

- меняют смысл;
- мешают пониманию;
- звучат заметно неестественно;
- часто повторяются;
- относятся к важной грамматической конструкции.

При необходимости показывать:

1. что сказал пользователь;
2. исправленный вариант;
3. естественный вариант носителя;
4. краткое объяснение.

Если ответ понятен и естественен, не нужно превращать его в длинный урок.

---

## 9. Mistake Memory

Значимые ошибки должны сохраняться.

Для каждой ошибки приложение может отслеживать:

- исходную формулировку;
- исправленный вариант;
- категорию;
- паттерн ошибки;
- количество повторений;
- дату первого появления;
- дату последнего появления;
- важность;
- статус усвоения.

Повторяющиеся ошибки должны влиять на будущие занятия.

Пример логики:

- одна ошибка → кратко исправить;
- повторилась → сохранить;
- повторяется снова → встроить в следующее занятие;
- устойчивый паттерн → создать micro lesson;
- после улучшения → проверить снова через некоторое время.

---

## 10. Произношение

Произношение является одной из центральных функций Language Teacher.

Для новых или сложных слов приложение должно помогать с:

- правильным звучанием;
- ударением;
- долгими и короткими звуками;
- редукцией;
- связной речью;
- интонацией;
- трудными фонемами.

Если произношение нельзя предсказать по написанию, это нужно явно показывать.

Полезно сравнивать звуки с другими языками пользователя, если это действительно помогает.

Приложение должно поддерживать:

- прослушивание образца;
- замедленное воспроизведение;
- запись голоса;
- повторное прослушивание;
- сравнение образца и записи;
- в будущем — автоматический pronunciation feedback.

---

## 11. Грамматика

Грамматика должна объясняться простым языком.

Порядок:

1. показать значение конструкции;
2. привести несколько естественных примеров;
3. кратко объяснить правило;
4. сразу применить его в речи.

Не перегружать терминологией.

Грамматика должна часто появляться из реальных ошибок пользователя, а не только из заранее заданной программы.

Например:

пользователь несколько раз допускает одну и ту же ошибку → приложение создаёт короткий 2–4-минутный micro lesson.

---

## 12. Словарный запас

Основная единица обучения — не отдельное слово, а **usable language**.

Предпочтение:

- устойчивым выражениям;
- chunks;
- типичным сочетаниям;
- естественным шаблонам;
- частотным современным словам.

Для нового слова или выражения полезно показывать:

- перевод;
- основные значения;
- произношение;
- естественные примеры;
- типичные сочетания;
- предлоги;
- регистр;
- похожие слова;
- отличия;
- происхождение, если это полезно.

Не следует нагружать пользователя редкими и устаревшими словами без необходимости.

---

## 13. Отдельные слова

Если пользователь вводит только одно иностранное слово или короткое выражение, Language Teacher должен по умолчанию давать:

1. перевод на язык интерфейса пользователя;
2. основные значения;
3. произношение;
4. естественные примеры;
5. типичные сочетания;
6. отличие от похожих слов, если полезно;
7. происхождение и этимологию.

Если значений несколько и они сильно различаются, разделять их.

---

## 14. Listening

Listening Training не должен сводиться к выбору правильного перевода.

Предпочтительная схема:

1. пользователь слышит речь без текста;
2. пытается понять;
3. слушает снова;
4. при необходимости видит текст;
5. приложение объясняет важные элементы живой речи;
6. пользователь отвечает;
7. выражение возвращается позже в другой ситуации.

Нужно постепенно увеличивать:

- скорость;
- естественность;
- длину реплик;
- количество незнакомых элементов;
- разнообразие говорящих.

---

## 15. Интервальное повторение

Language Teacher использует интервальное повторение, но не ограничивается простым вопросом «переведи слово».

Для каждого learning item желательно отдельно отслеживать:

- recognition;
- production;
- listening;
- pronunciation.

Пользователь может узнавать слово при чтении, но не уметь произнести его самостоятельно — приложение должно различать эти состояния.

Повторение должно требовать активного использования языка:

- закончить фразу;
- ответить собеседнику;
- сформулировать просьбу;
- воспроизвести выражение;
- понять его на слух;
- использовать в новой ситуации.

---

## 16. Adaptive Difficulty

Сложность адаптируется автоматически.

Если задания слишком простые:

- увеличивать долю изучаемого языка;
- уменьшать подсказки;
- повышать скорость речи;
- делать диалоги длиннее;
- добавлять неожиданные ответы собеседника.

Если пользователь систематически ошибается:

- временно упростить;
- дать больше примеров;
- уменьшить количество новых элементов;
- чаще повторять слабые конструкции.

Навыки оцениваются отдельно.

---

## 17. Real Life Mode

Одна из ключевых функций Language Teacher:

**I need this now / Мне нужно это сейчас.**

Пользователь описывает реальную ситуацию:

> Мне нужно объяснить хозяину квартиры, что под раковиной течёт вода.

Приложение:

1. предлагает естественную фразу;
2. даёт аудио;
3. позволяет потренировать произношение;
4. может запустить мини-диалог;
5. предлагает сохранить ситуацию для будущего обучения.

Так реальные жизненные события постепенно формируют персональный учебный курс пользователя.

---

## 18. Personal Situations

Пользователь может сохранять собственные сценарии:

- разговор с арендодателем;
- банк;
- автомастерская;
- врач;
- звонок;
- разговор с соседями;
- покупка;
- рабочая встреча;
- документы;
- путешествие.

Language Teacher должен использовать их в будущих занятиях.

---

## 19. Прогресс

Не делать основными метриками:

- XP;
- виртуальные монеты;
- сердечки;
- streak;
- leaderboard;
- crowns.

Показывать реальные навыки:

- Speaking;
- Listening;
- Pronunciation;
- Vocabulary;
- Grammar.

Также показывать реальные жизненные способности:

- могу заказать еду;
- могу спросить дорогу;
- могу объяснить проблему;
- могу поговорить с соседом;
- могу позвонить;
- могу решить вопрос в банке.

---

## 20. Стиль преподавания

Language Teacher должен быть:

- спокойным;
- терпеливым;
- конкретным;
- требовательным;
- практичным.

Не хвалить автоматически каждый ответ.

Лучше конкретно показывать:

- что получилось;
- что стоит улучшить;
- какая ошибка важна;
- что попробовать ещё раз.

Оптимальный цикл:

> короткое объяснение → практика → обратная связь → следующая практика.

---

## 21. Конечная цель

Пользователь должен постепенно:

- меньше переводить в голове;
- быстрее понимать живую речь;
- увереннее отвечать;
- употреблять естественные выражения;
- исправлять устойчивые ошибки;
- воспринимать язык как средство общения.

Language Teacher — не игра и не цифровой учебник.

Это **персональный языковой тренер с памятью, голосом, адаптивным обучением и ориентацией на реальную жизнь**.
